# Dogpatch backend (Convex)

Convex backend for the Dogpatch open-world game. It stores players, each player's saved state (position, heading, on foot or driving), and the world's vehicles. For Speed Dial it also runs four-player race rooms: the lobby and countdown, race positions, places and results, the world-change event log, and the Operator. Everything is exposed to the Unity client over plain HTTP/JSON. The full API is in [CONTRACT.md](CONTRACT.md).

The Unity client does not call this yet: it runs against a local in-memory `IGameBackend`. This project is the server side that a later `ConvexBackend` implementation will call.

## Layout

| Path | What it holds |
| --- | --- |
| `convex/schema.ts` | Tables: `players`, `playerStates`, `vehicles`, `rooms`, `roomPlayers`, `roomEvents` |
| `convex/players.ts` | `create`, `get` |
| `convex/playerState.ts` | `load`, `save` |
| `convex/vehicles.ts` | `list`, `enter`, `exit`, `update`, and the internal `seed` |
| `convex/rooms.ts` | `create`, `join`, `leave`, `setReady` (and rematch), and the internal `poll` |
| `convex/race.ts` | `update`: position, route progress and finish detection |
| `convex/events.ts` | `fire`: appends a world change to a room's log |
| `convex/operator.ts` | The voice Operator: `call`, `confirm`, `activeEffects`, `mintScribeToken`, expiry |
| `convex/operatorRules.ts` | The routing rules that turn Jev's answers into one command |
| `convex/operatorCatalogue.ts` | Effects, classes, durations, counters |
| `convex/jev.ts` | The Jev questions, the input text and the HTTP call |
| `convex/avatarData.ts` | Avatar questions' option lists, outfits, swatches, costume presets, thresholds and Polyfork base models |
| `convex/avatarModel.ts` | Avatar questions and the fixed rules from answers to avatar params |
| `convex/avatarDecision.ts` | The hedged decision call: Jev first, the backup after 1.5 s or on failure |
| `convex/avatarPhoto.ts` | The Node action: resize the photo with sharp, decide, map, save |
| `convex/avatars.ts` | Avatar table writes and `get` |
| `scripts/live-operator.mts`, `scripts/live-voice.mts`, `scripts/live-avatar.mts` | Live tests against a deployment |
| `convex/raceModel.ts` | Room rules: colors, countdown, phase, route progress, place order, awards |
| `convex/worldChanges.ts` | World-change validation and news text |
| `convex/model.ts` | Shared validators, error helper, and response shapes |
| `convex/http.ts` | HTTP routes for the Unity client |
| `convex/game.test.ts`, `convex/race.test.ts` | `convex-test` suites (functions and HTTP routes) |
| `convex/_generated/` | Generated by the Convex CLI; committed so typecheck and tests work without a deployment |

## Setup

Node 22 or newer and pnpm.

```sh
cd backend
pnpm install
```

## Test and typecheck

Neither needs a deployment or a Convex account.

```sh
pnpm test        # vitest + convex-test, in-memory backend
pnpm typecheck   # tsc over convex/ and the tests
```

## Develop

```sh
pnpm dev         # npx convex dev
```

The first run asks you to log in and pick or create a Convex project, then writes `CONVEX_DEPLOYMENT`, `CONVEX_URL`, and `CONVEX_SITE_URL` to `.env.local` (gitignored). It pushes functions on every save and regenerates `convex/_generated/`; commit the generated files when they change.

Without an account, `CONVEX_AGENT_MODE=anonymous npx convex dev` runs a local backend on `http://127.0.0.1:3210` with HTTP actions on `http://127.0.0.1:3211`.

Seed vehicles once per deployment (it does nothing if any vehicle exists). Coordinates are Unity world space, so take them from the client's spawn points:

```sh
npx convex run vehicles:seed '{"vehicles":[{"model":"hatchback","position":{"x":120,"y":0.5,"z":-40},"heading":90}]}'
```

Add `--prod` to seed the production deployment.

Try an endpoint:

```sh
curl -X POST "$CONVEX_SITE_URL/api/players" -H 'Content-Type: application/json' -d '{"displayName":"Tim"}'
curl "$CONVEX_SITE_URL/api/vehicles"
```

## The Operator

The Operator needs two deployment env vars: `AI_GATEWAY_API_KEY` (Vercel AI Gateway, for `typesafe-ai/jev`) and `ELEVENLABS_API_KEY` (for Scribe tokens). Set them with `npx convex env set <NAME> <value>` on every deployment, or add them as project defaults in the Convex dashboard. Without the gateway key, every call is refused as `unavailable`. See "The voice Operator" in [CONTRACT.md](CONTRACT.md).

Live tests (they create throwaway players and a room on the deployment):

```sh
CONVEX_URL=https://<deployment>.convex.cloud npx tsx scripts/live-operator.mts   # 45 phrases across every scope and refusal
CONVEX_URL=https://<deployment>.convex.cloud npx tsx scripts/live-voice.mts      # macOS say → Scribe → Operator, release-to-effect timing
```

## Deploy

```sh
npx convex deploy
```

Interactively this deploys to the production deployment of the project you linked with `convex dev`. In CI or on a machine without a login, set `CONVEX_DEPLOY_KEY` (from the Convex dashboard: Settings → Deploy keys) in the environment and run the same command; never commit the key. The client's base URL is the deployment's `https://<name>.convex.site`.
